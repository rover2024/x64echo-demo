# How X64Echo Works

X64Echo starts from the library pass-through infrastructure already available
in QEMU user-mode. A QEMU plugin registers a syscall filter. The filter
recognizes a reserved syscall before QEMU treats it as a Linux syscall, and the
`dlcall` plugin performs host-side library loading, symbol lookup and native
invocation.

Lorelei uses this mechanism for C interfaces. X64Echo keeps the mechanism
generic and moves C++ ABI adaptation into artifacts generated by the compiler.

## Two Artifacts

From one unmodified C++ library source, the X64Echo compiler emits:

- a **face** library for the guest ISA and ABI;
- a **native** library for the host ISA and ABI.

The guest dynamic linker loads only the face. The host loads the native
library through `dlcall`. A small bootstrap handshake connects the two.

## Calls

A guest call enters a face stub, which packages a transfer record and issues
the reserved syscall. QEMU consumes the syscall, and the plugin calls the host
runtime. The native runtime dispatches to an adaptation entry generated for the
original C++ function.

This separation matters because C++ arguments and return values may involve:

- classes passed by value;
- hidden structure-return pointers;
- register-pair aggregates;
- exceptions and compiler-generated cleanup;
- variadic arguments.

## Callbacks and Re-entry

A native library may call a guest function pointer or a virtual override on an
object supplied by the guest. The native call parks its current invocation in a
coroutine and returns control through the original syscall path. The guest runs
the callback, then resumes the parked native invocation.

## Object Model

Both sides use the guest representation as the canonical object identity.
Virtual tables, secondary vtable pointers, RTTI descriptors, allocation and
deallocation are adapted so pointer comparisons, casts, callbacks and object
lifetimes continue to work across the boundary.

## Boundaries

X64Echo does not modify the guest executable or either dynamic linker. It also
does not require a modified QEMU. The current implementation still has limits
around concurrency, coroutine switches and some teardown paths; see
[limitations.md](limitations.md).
